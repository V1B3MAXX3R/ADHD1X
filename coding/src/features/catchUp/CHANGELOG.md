## 2026-10-14 - Each class on its own; paces set up from the due dates
- Made by: Claude
- Changed: catchUpModel.ts gives each class its own result (ClassNeed: grade now, tasks needed, hours, past due, tasks left) and each pace a result for each class (ClassPace: caught-up day, late tasks, last task, on track). It works out the least time a day that keeps every class on track, in 15-minute steps (minutesNeeded). Chill (usually 1.25 hours) goes up to 2 hours and Normal (2.5) up to 3.5 when that is needed (PACE_MAX_MINUTES); Aggressive keeps your hours. Past-due work should be done by your goal date, else the term's last day (limit); a goal after the last day uses the last day. A pace is possible when every class that can still reach a C is on track. Tasks that cannot be on time at any pace (due too soon for their size) are named and not judged. cGoal.ts starts each class's C math from its grade now (gradeBook.ts knownGrade: the grade you typed, else Canvas's current score, never a hidden one); when that differs from what the scores add up to, the difference is kept for the part of the grade already graded (GradeBook.shareOf). The grade now counts 0s, including a 0 you plan to turn in. studyPlan.ts plans past-due work one class at a time, the class with the least left first and the oldest first inside it, and gives a class whose C is out of reach only the time left over (lowPriorityCourseIds). New page order: Your classes (each with its grade now and tasks left), Grading (a My grade now box for each class), Late work, What each class needs for a C (one block per class, no combined total), By due date, Your pace (the goal date folded in, one line per class for the chosen pace), Your study plan (Plan all my work moved here, and a Show menu for one class), then the score math. DeadlinePicker.tsx removed.
- Why: Christian saw about 200 for a C across all his classes and asked for the focus to be on each class (each needs a C or above), for each class's grade to be part of the settings and to shape the planner and the pace, and for the pace not to treat all the work as one big class. He also asked to keep the screen uncluttered, to put the pace after the assignment reasoning, and for the pace to set up its modes from due dates, time, the end of the semester and other factors.
- Notes: A class with no Canvas number and nothing typed in gets the same C as before. Normal's top (3.5 hours) stays below Aggressive's usual 4 so the two differ. The pace sizes and ranges are not in the decision log (see open items). A full run on his real file takes 15 to 40 ms.

## 2026-10-14 - Due dates first; grading for each class; By due date
- Made by: Claude
- Changed: catchUpModel.ts rewritten: each class's fewest tasks for a C by the end of the term (a class that cannot reach a C never blocks the others), then those tasks planned by due date, then the pace (hours a day) gives the day past-due work is caught up. studyPlan.ts can plan by due date: it keeps time free before each due date so nothing new goes late, puts past-due work after that, and starts upcoming work in the week before it is due (KEEP_UP_DAYS). gradeBook.ts puts your own grading setup first (categoryFromSetup: picked by hand, then Canvas category, then a word in the name, then your default), then Canvas, then points with a C at 70% (connectionSummary counts what each category holds). New GradingSection (cutoffs, points or weights, categories with weight, words and drop lowest, a default category, connecting by hand, removing with a confirm) and DueDateView (past due, next 7 days, the week after, later, after the goal; each item says if it is needed for a C and the day it is planned; Help me start; I finished this). dueBuckets.ts holds the groups and CURRENT_WORK_DAYS: work due more than 180 days ago is left out, and ticked classes with nothing from this term are named as left out. The grade on graded work counts 0s, like Canvas. A caught-up day after the term's last day says Not caught up this term. DueSoonestQueue.tsx removed.
- Why: Christian found that ticking several classes bundled all the work into one heap before one due date (Catch Up said everything was due by December 12). He asked for work to be sorted by due date before the pace comes in, for Catch Up to know a C does not need every assignment (read the points), and for a grading-standard setting for each class that he can type in, connecting assignments by hand if needed.
- Notes: Tests for the new engine are in the entry above.

## 2026-10-14 - Grades worked out the way Canvas does; a fix in Enough for a C
- Made by: Claude
- Changed: New gradeBook.ts: category weights (only categories with work count, scaled to fit, as Canvas does), drop-lowest and drop-highest rules, and each class's own C cutoff from its letter scale. Enough for a C and Target grade and score math both use it, so they match each other and Canvas. The C box now gives each class's grade now, the C cutoff, what is still needed (percentage points of the grade; points too for classes graded by points) and Canvas's own grade. Late work: a 0 on work Canvas shows as turned in is a real grade, not late work; work past its Canvas lock date cannot be planned (shown as closed); a redo request makes work to do again. Each class in Late work has a From Canvas box (grade, weights, drop rules, C cutoff, late policy, modules, announcements, syllabus) and each assignment row shows Canvas flags and an Open in Canvas link. Fixed: in Enough for a C, every class that was not a stretch showed a wrong sentence ('a C needs about undefined%...') because of a misplaced condition.
- Why: Christian asked the Canvas tool to pull everything it safely can. Before this, the tool read only scores, so Catch Up could not match Canvas for weighted classes (ITIS-55 showed 28% in Canvas but 14% on points) and could not tell a missing 0 from a real one.
- Notes: Classes graded by points give exactly the same answers as before (tests check). Canvas chooses which scores to drop a little more carefully than this does, so a class with drop rules can differ slightly. A syllabus-to-Courses-page button was tried and left out: that page makes a new class, which would duplicate classes and assignments already brought in from Canvas. Not yet in the decision log.

## 2026-10-14 - No more two-week fallback; says the hours a C would take
- Made by: Claude
- Changed: The fixed two-week window is gone everywhere. With no date picked yet, or a past date, the soonest date that works is used. When no pace can reach a C this term, or there are no point values, the window is the rest of the term (or 120 days with no last day), and the page says so plainly instead of showing a date you cannot reach. The model now works out the hours a day a C would take by your goal date (or the end of the term). When no pace makes it, the notice says that number and offers 'Use Aggressive at N hours a day' (split across Morning, Evening and Night, up to 6 each). If a C is out of reach on the points, it says time would not help.
- Why: Christian chose the automatic goal date and saw October 28, a date he could not reach. When no pace could reach a C, the page had quietly fallen back to the next two weeks and shown that as the date. He had asked for the two-week deadline to be removed.
- Notes: FALLBACK_WINDOW_DAYS removed from deadline.ts. Not yet in the decision log.

## 2026-10-14 - Every assignment in the dropdown, and a realistic C
- Made by: Claude
- Changed: (1) The Late work dropdown lists every assignment in the class, in three groups: Late (not turned in, or scored 0), Coming up, and Turned in or graded. Late and upcoming work starts in the plan and can be unticked; turned-in work starts out and can be ticked to redo or resubmit. Work set to Not now is counted but left out. Each row says Not turned in, Scored 0, Scored N of M, or Turned in, not graded yet. (2) A C that needs more than your usual score but no more than 90% on the work left now counts as possible. The plan picks the fewest tasks that reach it at that higher score, instead of asking for every task. Above 90% it is still called very hard. (3) New helpers in deadline.ts: assignmentGroup and planChoices; cGoal.ts: realisticC and REALISTIC_MAX_PERCENT. New saved field catchUp.planAddedIds.
- Why: Christian asked for the late work dropdown to list every assignment, read from his assignments, and said Catch Up still told him he could not get a C. A local run on his Canvas file showed three causes: a C needing 70.6% was called impossible because the assumed score was 70%, Canvas work not graded yet (including missing work) was never imported, and every imported item got a full default time (a 1-point lab counted as 3 hours).
- Notes: On Christian's file this changes the answer from no C to: Aggressive (4 hours a day) gets every class to a C by Nov 29; Normal and Chill cannot before the term ends. The time guesses are still guesses; changing an assignment's time changes the dates. Not yet in the decision log.

## 2026-10-14 - One shared Catch Up model; 0s count as late work; every pace checked against the goal date
- Made by: Claude
- Changed: (1) New catchUpModel.ts works out everything once (classes, late work, goal date, C goal, all three paces, the plan) and every section reads from it: Late work, Your goal date, the pace cards, Enough for a C, the study plan, the score math, and the Catch Up bar on Today. (2) A past-due assignment scored 0 now counts as late work (gradebooks often put a 0 on missing work without marking it missing). It shows in the Late work list as 'Scored 0' and, while it is in the plan, the math counts it as work still to do; the saved score is never changed. Taken out, or in a class that does not accept late work, it stays a 0. (3) Each pace is checked against the goal date. With your own date, a pace that cannot finish the C work by then shows 'Not possible by <date>' with its soonest date, and cannot be picked. If the chosen pace cannot make it, a notice says so and offers Switch to <lightest pace that works> and Move my goal date to <soonest date at this pace>; if no pace can, it says so and offers the soonest date. If a C is out of reach on the points by that date, it says that instead. With the automatic date, each pace gets its own soonest date, and the chosen pace's date is the one used. (4) The soonest date is the first goal date where a C is reachable on the points and the C work, at that pace, is done by that date, so moving to a suggested date always works. (5) Every pace now plans just enough for a C by default, with 'Plan all my work' for any pace. The earlier late-task pace advice is replaced by this check. (6) Basic checks: a goal date in the past or missing, after the term's last day, on a break, or before anything is due are each named plainly. (7) Sections are now: 1 Your classes, 2 Late work, 3 Your goal date, 4 Pick your pace (with Enough for a C), 5 Your study plan, 6 Target grade and score math, 7 Due soonest.
- Why: Christian found that 0s in his gradebook were not treated as late work, and that the paces and the Enough for a C box did not follow the goal date (for example, Chill was still offered for a goal date it could not meet). He asked for every part to work together and read from each other.
- Notes: Removed advisePace (cGoal.ts) and resolveDeadline (deadline.ts); deadline.ts now holds small helpers. cGoal has a new status, nothingDue, for a class with nothing worth points due by the date. buildCatchUpPlan takes precomputed study days. The whole model takes about 50 ms on a term of 600 assignments, so no faster language is needed. Not yet in the decision log.

## 2026-10-14 - Catch-up deadline, and a Late work section
- Made by: Claude
- Changed: (1) New section 2, Your catch-up deadline: automatic (the nearest date every ticked class can reach a C at your usual score, searched day by day up to the term's last day, or 120 days) or a date you pick. A picked date shows what it takes: tasks and hours for a C, hours a day over the study days left (break days skipped), and whether your pace fits. The fixed 14-day window is gone; two weeks is used only when there is no date yet, the date has passed, or no date works. The plan and pace advice now say whether they fit before your deadline when you picked one, else before the last day of the term. (2) New section 3, Late work: each ticked class has four choices (Late work waived, deducted at 10%, deducted at 50%, not accepted). Where late work is accepted, a list opens with that class's late assignments; each can be in or out of the study plan, with Add all and Take all out. They all start in the plan. Not accepted leaves past-due work in that class out of the plan and the C goal (the points still count as lost). The old late-penalty control inside Your classes is removed (LatePenaltyControl.tsx deleted). (3) Sections renumbered 1 to 7. New files: deadline.ts, components/DeadlinePicker.tsx, components/LateWorkSection.tsx. cGoal.ts takes unavailableIds.
- Why: Christian asked for a personal catch-up deadline (a date he picks, or the nearest date the site finds that he can reach a C) in place of the fixed two weeks, and for late work to have its own section with four choices per class and a list of late assignments to pick from.
- Notes: Late work you take out is saved in settings (catchUp.lateSkippedIds), so it stays out after a reload. The deadline mode and date are saved too. Automatic needs point values to judge a C; a class with none is ignored for the search, and if no class has any, the two-week fallback is shown. Today's Catch Up bar still counts the next two weeks. Not yet in the decision log.

## 2026-10-14 - C goal: fair assumed score, and clear answers when a C is a stretch or out of reach
- Made by: Claude
- Changed: (1) The assumed score now ignores zeros for work never handed in (they were dragging it down to 50%, which made a C look impossible when a gap of missing work was the real cause). It uses your average on work that earned points, kept between 70% and 90%, and 80% with none. (2) When your usual score is not enough, the class now says one of two plain things instead of 'not enough': 'a C needs about N% on everything due now and in the next two weeks' (a stretch, still possible), or 'even full marks would reach about N%' (out of reach on that work). Every task in the window stays in the plan either way.
- Why: Christian pasted four classes where the C goal said the work left was not enough to reach it 'at about 50%' and told him nothing useful.
- Notes: The window is still graded work plus work due already or within 14 days, so 'out of reach' means out of reach on that work alone. Later work in the term could still change it. Not yet in the decision log.

## 2026-10-14 - Pace cards match the plan, better-pace advice, and Aggressive plans just enough for a C
- Made by: Claude
- Changed: (1) The pace cards now read from the same plans as the study plan, so the days always agree (including break days and split tasks). Hours show to two decimals (1.25, not 1.3). The longest plan is now 366 days instead of 120, and a plan that is still cut off says 'N days or more'. (2) Better-pace advice: only when the chosen pace leaves tasks finishing after their due dates, or runs past the last day of the term, and a faster pace does better. It names the lightest pace that does as well as the fastest, says what changes, and has a Switch button. It stays quiet otherwise. (3) Enough for a C (cGoal.ts, CGoalCard.tsx): for each ticked class, works out the points still needed for 70%, assuming you score what you have been scoring (50% to 95%, or 80% with nothing graded yet), counts finished but ungraded work, and picks the tasks with the most points for the time until that is covered. Each pace card shows 'A C: N days' and 'All the work: N days'. The Aggressive pace plans only those tasks, with a checkbox to plan everything; Normal and Chill plan everything. When a class is already at a C it says so, and says Catch Up can be switched off. A class with no point values has all its work included; a class that cannot reach a C says so and includes everything.
- Why: Christian saw the pace cards and the study plan disagree (188 days against a plan cut off at 120, and 1.25 hours shown as 1.3), and asked for advice on a better pace when assignments are at risk, and for Aggressive to plan just enough work for a C and say how long that takes.
- Notes: A C is fixed at 70% and is judged on points, not on syllabus category weights; the card says so. Advice compares the plans for all the work, so work that is already past due counts as late at every pace. Late penalties lower the value of work that is already past due. Nothing here is sent to Gemini. Not yet in the decision log.

## 2026-10-14 - Last day, midterms and finals modes, breaks, and Aggressive hours in blocks
- Made by: Claude
- Changed: (1) Last day: Catch Up now looks ahead to the term's last day instead of a fixed 14 days when one is set, and the plan says whether it fits before that day. (2) Breaks: the study plan plans nothing on break days and moves the work to the next free day; it says how many break days it skipped. (3) Midterms and finals modes: exams are planned ahead of other work that is due on or after the first exam. Work due before the first exam stays first. (4) Aggressive pace: three hour choices (Morning, Evening, Night, 0 to 6 in half hours, default 1.5 / 1.5 / 1) whose total is the daily amount. The plan fills Morning, then Evening, then Night, and a block set to 0 is left out. The days-by-pace numbers on the pace cards and on Today use the same hours. Normal and Chill are unchanged. New files: termLogic.ts, components/AggressiveHoursPicker.tsx. Changed: studyPlan.ts (buildCatchUpPlan), catchUp.ts (computeCatchUpPaces takes minutesByPace), PacePicker, StudyPlan, CatchUpPage.
- Why: Christian asked for the term's last day to show in regular mode and Catch Up, a midterms mode and a finals mode, breaks, and for the Aggressive pace to use Morning, Evening and Night blocks shaped by how many hours he is willing to work.
- Notes: With no last day, no breaks, Regular mode and the default hours, the plan is the same as before except that Aggressive now totals 4 hours cut into blocks (it was one 240-minute lump). The default total is still 4 hours. The mode only changes the order, not the pace. If every day were a break, the plan stops with the usual 'plan stops early' note. Not yet in the decision log.

## 2026-10-14 - Several classes in one plan, late penalties, what-if scores with reset
- Made by: Claude
- Changed: (1) 1. Your classes: tick the classes to plan together (All classes, Only classes with work left). The grade math, pace and study plan use only the ticked classes; at least one must stay ticked. (2) Late penalty per ticked class: a checkbox, then 10% off or 50% off. Unticked means waived (late work still earns full points). Work already past its due date, and work the plan would finish after its due date, loses that share of the points you can still earn; the answer says how many points that costs. (3) Score math now gives one answer per class instead of mixing classes into one total. The quick check from your gradebook is for a single class. (4) What-if scores: the score boxes no longer save anything. They are what-ifs, tagged and counted, and Reset to my real numbers puts everything back (it also clears the quick-check boxes). Save what-if scores as my real scores keeps them, after a second tap. (5) 4. Your study plan: one day-by-day plan across the ticked classes, due soonest first, each day holding the chosen pace, big tasks split across days, with tasks that would finish after their due date listed with what a penalty would cost. New files: studyPlan.ts, components/{CourseChooser, LatePenaltyControl, StudyPlan}.tsx; GradeCalculator and the page were rewritten.
- Why: Christian asked for Catch Up to have a late penalty option per class (waived, 10%, 50%), a reset button for mock grade changes, and the ability to combine several classes into one plan and study plan.
- Notes: Before this change the score boxes saved straight over real scores as you typed, which would have overwritten grades imported from Canvas; that is why the what-ifs are separate. Late penalty is a new saved field on the class (latePenaltyPercent: 0, 10 or 50; missing means waived), and selectedCourseIds is new in the Catch Up settings; older saved data loads unchanged. With no penalties set, the grade math gives exactly the old answers (a test checks it). What-if scores are lost when you leave the page. Heading numbers moved to 1 to 5. Not yet in the decision log (A36, A39, A40, A81 are related).

## 2026-10-13 - First version
- Made by: Claude (from Gemini's Bucket 2 Part 2 files)
- Changed: New page at `/catch-up` ("Hyperdrive" in Space style, "Catch-up mode" in Regular style, A56). It has the on/off switch, a target-grade calculator (quick Canvas percent, or points from each assignment), three paces with the real number of days each takes (A81), and a Due soonest list that includes unfinished work from earlier dates (A39, A40). All grade math is plain code in `catchUp.ts` and never goes to Gemini (A36).
- Why: Christian's Catch Up / Hyperdrive request; decisions A35 to A40, A56, A81.
- Notes: Changes from the pasted code, to follow the decision log: (1) it is never offered. Today shows the Catch Up bar only after the person has switched it on (A39). (2) Picking a pace does not switch the mode on. (3) The days estimate looks only at work due within 14 days or earlier, so far-off assignments do not inflate it. (4) The score field can also set the points a task is out of, instead of silently setting 100. (5) Calmer wording: no warnings or "behind". A unit test checks that no grade or Catch Up setting can appear in any Gemini request code.
